# InteriorEstimation

数量と単価から**内装の見積り**を組む。1 スキャン分の数量リストを受け取り、
工種ごとに材料費と施工費を積んで直接工事費まで出す。

```bash
uv sync
uv run estimate run examples/quantities.json \
    --prices examples/prices.csv --trades examples/trades.csv
```

## 何を持ち、何を持たないか

**数量は拾わない。** 受け取った数量に単価を掛けて明細にするところだけを持つ。
壁の面積を出す、開口部を差し引く、家具を数える——どれもスキャンや図面の形を
知っている側の仕事で、ここへ持ち込むと**上流の数だけ拾い方が増える**。

| | |
|---|---|
| 持つ | 数量 × 単価、ロスと歩掛り、科目ごとの小計、諸経費・値引き・消費税、丸め、書き出し |
| 持たない | 面積・個数の拾い出し、3D、図面、内装制限が掛かるかの判定 |

そのぶん入力の形は**上流に依存しない**。[CaptureVisualizer][cv] の `room.json`
も [MiniCAD][mc] の図面も、呼ぶ側でこの形に直してから渡す。

[cv]: https://github.com/24th-garnet/CaptureVisualizer
[mc]: https://github.com/24th-garnet/MiniCAD

## 入力 1 — 数量リスト

```json
{
  "scan_id": "room-0a3f",
  "name": "ワンルーム 内装改修",
  "estimate": {
    "number": "2026-1013-001",
    "revision": 1,
    "issued": "2026-10-13",
    "valid_days": 14,
    "client": "見本 太郎",
    "subject": "ワンルーム 内装改修工事 お見積書"
  },
  "items": [
    {"code": "WC-1000", "qty": 48.6, "note": "壁。開口部 3 箇所を差し引き済み"},
    {"code": "DR-0100", "qty": 2},
    {"code": "SOFA-3P", "qty": 1, "note": "置換アセット abo/B07XYZ"}
  ]
}
```

品目コードと数量だけ。`note` は明細にそのまま出るので、**どこを拾った数量なのか**を
書いておくと後から追える。

### 頭書き（`estimate`）

**明細を作ってから足せない。** 既に出した見積りを後から識別できないし、どの単価で
出したのかも復元できない。電子帳簿保存法が電子で授受した見積書に求める検索の
手がかりは**取引年月日・取引金額・取引先**の 3 つで、金額は明細から出るが、
残り 2 つはここにしか無い。

| | |
|---|---|
| `issuer` | **発行者**（社名・住所・電話・担当・登録番号）。[下記](#発行者) |
| `number` | 見積番号 |
| `revision` | 版。出し直すたびに上げる |
| `issued` | 発行日（取引年月日） |
| `valid_until` / `valid_days` | 有効期限。日付か、発行日からの日数。**両方は書けない** |
| `client` | 取引先 |
| `subject` | 件名 |

`estimate` は**省略できる**（検算だけしたいときに番号を切りたくない）。ただし書くなら
`number` と `issued` は揃えて書く。片方だけでは後から見積りを特定できない。

### 発行者

```json
"issuer": {
  "name": "○○内装 株式会社",
  "address": "東京都…", "tel": "03-0000-0000",
  "person": "積算 花子",
  "registration": "T0000000000000"
}
```

**宛先があるのに発行者が無い文書は、見積書として成立しない。** 省略はできるが、
その場合は紙に「発行者が未記入」と出る。黙って出さない。

`registration` は適格請求書発行事業者の登録番号。見積書は適格請求書ではないので必須
ではないが、**後から請求書に起こすときに要る**のでここで持っておく。**形は検査しない**
——変わる可能性のあるものを、こちらが決め打ちで断るべきではない。

**数量に単位を書かない。** 単位は単価表が持っている。両方が持つと、食い違ったとき
どちらが正かを決められない。

**同じコードが 2 行あっても合算しない。** 「居間の壁」と「寝室の壁」は同じクロス
でも別の行として見せたい。合算すると見積書から現場が消える。

**0 以下の数量は断る。** 拾えなかった行は、渡す前に落とす。0 の行を通すと「拾って
0 だった」のか「拾い忘れた」のかが見積書から分からなくなる。

JSON は `parse_float=Decimal` で読む。`48.6` を float で受けると末尾が濁り、
積み上げた合計が 1 円ずれる。

## 入力 2 — 単価表

**単価はリポジトリに持たない。** 価格は出どころと使用条件が物ごとに違い、年ごとに
改定される。手元の CSV を指して使う（[TemplateMaker][tm] が GLB を持たないのと
同じ理由）。`examples/` にあるのは**形式の見本で、単価は架空**。実勢価格ではない
（[examples/NOTICE.md](examples/NOTICE.md)）。

[tm]: https://github.com/24th-garnet/TemplateMaker

`prices.csv` — 品目ごと

```csv
code,name,unit,division,section,material,loss,labor,trade,tax,source,as_of
WC-1000,量産クロス,㎡,内装工事,壁・天井仕上,450,0.05,0.10,内装工,課税,A 商事 見積,2026-03-11
FL-2000,複合フローリング,㎡,内装工事,床仕上,4200,0.05,0.25,大工,課税,建設物価 2026-04,2026-04-01
DR-0100,片開き戸(枠・金物共),箇所,建具工事,木製建具,42000,0,0.8,建具工,課税,B 建材 見積,2026-02-20
INS-0100,工事保険料,式,諸費用,保険,32000,0,0,,非課税,保険料率表,2026-04-01
```

| 列 | |
|---|---|
| `unit` | 数量の単位。㎡ / 箇所 / 台 / 本 / 枚 / 式 |
| `division` | **科目**。内訳書の一番上の段 |
| `section` | **中科目**。科目の中の区分 |
| `material` | 材料単価（円 / 単位） |
| `loss` | ロス率。`0.05` で 5% |
| `labor` | 歩掛り（人工 / 単位） |
| `trade` | 職種。空なら手間なし |
| `tax` | 税区分。課税 / 非課税 / 不課税。省略すると課税 |
| `source` | 単価の出どころ |
| `as_of` | その単価を採った日 |

右の 8 列は**無くても読める**。既にある表をそのまま読めないと入れ替えが進まない
ため。`prices` コマンドが読めた任意列を出し、**出どころや認定の書かれていない品目を
数えて出す**。

### 認定・等級

| 列 | 値 | |
|---|---|---|
| `fire` | 不燃 / 準不燃 / 難燃 / 対象外 | 建築基準法 内装制限 |
| `fire_no` | 認定番号。自由記述 | 〃 |
| `f_star` | F☆☆☆☆ / F☆☆☆ / F☆☆ / 規制対象外 / 無等級 | シックハウス規制 |
| `flame` | 防炎 / 非防炎 / 対象外 | 消防法 8 条の 3 |
| `spec` | 寸法・仕様。自由記述 | |

**このモジュールは内装制限が掛かるかを判断できない。** 建物の用途・規模・階数を
知らないため。だから「欄を持ち、空欄を数えて見せる」までが担当で、**空欄＝誤りとは
限らない**（家具に不燃認定は要らない）。

そのために `対象外` を語彙に入れてある。**3 つの状態を分ける**のが要点。

| | |
|---|---|
| 値（`不燃` など） | 表を組んだ人が区分を書いた |
| `対象外` | 表を組んだ人が「この品目に内装制限は当たらない」と判断した |
| 空欄 | **まだ誰も見ていない** |

これが無いと、家具も建具も電気も全部「不燃区分が空」で挙がる。17 行中 14 行が
報告に出る見本は、誰も直さない。

**`fire_no` は検証しない。** 令 108 条の 2 の例示仕様（コンクリート・ガラス・
金属板など）は認定番号を持たず、枝番・複合認定・旧書式もある。形を強制すると実データ
が通らない。代わりに**接頭辞が区分と食い違う行だけを数える**（`不燃` なのに `QM-`）。
打ち間違いだけを拾い、書き方の多様性は拾わない。

`f_star` の `規制対象外` と `無等級` は**別のもの**。前者は告示の対象建材ではない
（金属・ガラス・無垢材）、後者は第一種発散建築材料で原則使えない。混ぜると、使える
建材と使えない建材が同じ欄になる。

**`--strict` には入れない。** `--strict` の根拠は「合計が足りない」で、認定欄の空欄は
合計を 1 円も変えない。判定できないことを根拠に落とすのは越権でもある。

`--prices` / `--trades` を省くと、作業ディレクトリの `prices.csv` と `trades.csv`
を見る。手元の単価表はその名前で置けば毎回指さずに済む（`.gitignore` 済み）。

`trades.csv` — 職種ごと

```csv
trade,name,daily
内装工,内装仕上工,24000
大工,大工,26000
```

**施工費を円で直に持たない。** 歩掛りと労務単価を分けて持つと、労務単価が改定された
とき 1 行直せば全品目に行き渡る。円で持つと品目の数だけ直すことになり、直し漏れた
品目が古い相場のまま残る。

## 入力 3 — 経費表

```csv
kind,stage,name,base,rate,amount,after,tax,source,as_of
経費,1,共通仮設費,直接工事費,0.062,,純工事費,課税,共通費積算基準,2026-04-01
経費,2,現場管理費,累計,0.095,,工事原価,課税,共通費積算基準,2026-04-01
経費,3,一般管理費等,累計,0.082,,工事価格,課税,自社 2026 期,2026-04-01
消費税,,消費税,課税,0.10,,,,国税庁,2019-10-01
```

民間リフォームの 1 段ならこれだけ。

```csv
経費,1,諸経費,直接工事費,0.15,,工事価格,課税,自社 2026 期,2026-04-01
消費税,,消費税,課税,0.10,,,,国税庁,2019-10-01
```

| 列 | |
|---|---|
| `kind` | `経費` / `消費税` |
| `stage` | 段の順。1 から連番。**欠番も重複も断る** |
| `base` | 率の基数（`直接工事費` / `累計`）。消費税行では**掛ける税区分** |
| `rate` / `amount` | 率か固定額。**両方は書けない** |
| `after` | 足したあとの累計の呼び名（`純工事費` / `工事原価` / `工事価格`） |

**段の順は表に書かせる。** 科目の並びは見た目の問題だが、**ラダーの順は金額を変える**。
行を入れ替えたら静かに総額が変わる表は持ちたくない。

**消費税率もこの表に置く。** 案件ごとではないので数量リストには置けないが、価格と
同じで年と制度で変わるのでコードにも置けない。`base` が「何に掛けるか」で一貫するので、
軽減税率が要る日に行を 1 本足すだけで済む。

**経費表が無いときに黙って 0 にしない。** `--markup` を明示したのに無ければ断り、
既定の `markup.csv` が単に無いだけなら明細の合計までで止めて 1 行添える。
「諸経費 0 円の見積り」と「付け忘れた見積り」は見積書から区別が付かない。

## 諸経費・値引き・消費税

```
課税分                   1,535,033
  共通仮設費      6.2%      95,172   ← 直接工事費に掛ける
純工事費                 1,630,205
  現場管理費      9.5%     154,869   ← 直前の累計に掛ける
工事原価                 1,785,074
  一般管理費等    8.2%     146,376
工事価格                 1,931,450
  端数お値引き            -4,177
課税対価の額             1,927,273
  消費税          10%     192,727
  非課税                   32,000   ← 素通り
  不課税                   18,000   ← 素通り
見積合計（税込）         2,170,000
```

**率の基数は課税分だけ。** 非課税（保険料）と不課税（立替金）は段に触れず、税抜合計で
合流する。立替金は自治体に納める実費を預かっただけなので、**そこに管理費を乗せた瞬間に
立替ではなくなる**。保険料の手配に手数料を取りたいなら、固定額の段か課税の品目として
別の行で見せる。

だから**率の段の税区分は課税だけ**で、非課税・不課税を名乗れるのは固定額の段に限る。
「ロス率は材料にだけ掛ける」と同じ性質の決めで、設定で選べるようにすると誤った方を
選べてしまう。

**段は行である。** 見積書の上で共通仮設費 95,172 は小計ではなく新しく足す 1 行なので、
行と同じく 1 回だけ丸める。累計は丸め済みの段を足すだけ。基数は常に丸め済みの整数に
なるので、丸めは構造的に「整数 × 率」の 1 回しか起きない。

**基数を明細に残す。**「この 154,869 は何に 9.5% を掛けたのか」が無いと検算できない。

端末ではラダーの基数を **「課税分」**と呼ぶ。「直接工事費」とは呼ばない —— 単価表に
課税の諸費用科目を置けるので、明細の課税分は直接工事費とは限らない。

### 値引き

```json
"discount": {"name": "お値引き", "amount": 27205}
"discount": {"name": "端数お値引き", "target": 2170000, "basis": "税込"}
```

**額指定を勧める。** 目標額から逆算した値引き額は税率に依存するので、税率が変わると
過去の見積りを同じ数で再現できない。

**端数調整には到達できない目標がある。** 税込合計 = X + ⌊0.1X⌋ + 非課税 ＋ 不課税 は
X を 1 増やすと 1 か 2 増える。

```
X=1,600,009 → 1,810,009
X=1,600,010 → 1,810,011     ← 1,810,010 は存在しない
```

16 万件の範囲で数えると **9.1% の目標が到達不能**。1 円ずれた額を黙って返さず、
到達できる前後の額を添えて断る。

```
値引き: 税込 1,810,010 ちょうどにはできない。1,810,009 か 1,810,011 になる
```

値引きは課税売上に係る対価の返還なので、**課税分からだけ引き、消費税の前に引く**。

## 計算の規約

| | |
|---|---|
| 材料費 | 数量 × (1 + ロス率) × 材料単価 |
| 人工 | 数量 × 歩掛り |
| 施工費 | 人工 × その職種の労務単価 |

**ロス率は材料にだけ掛ける。** 切り代や張り代で材料は余分に要るが、張る手間は増え
ない。材料と手間に同じ率を掛けると、面積の大きい部屋ほど手間が実態から離れていく。

**人工は丸めない。** 0.25 人工を切り上げると、台数の多い照明で手間が倍になる。

**丸めるのは行の金額だけ。** 円未満を切り捨てる（積算の慣習）。小計と合計は丸め済み
の行を足すだけで、二度目の丸めをしない。先に小計を丸めてから足すと、合計と行の和が
食い違い、**どの行から来た差なのか説明できなくなる**。

金額は Decimal で持つ。0.1 + 0.2 が 0.3 にならない型で単価を積むと合計が 1 円ずれ、
1 円ずれた見積書は根拠を説明できない。

**科目と中科目の並びは単価表に出てきた順。** 名前順に並べ替えると、表を組んだ人が
意図した工事の順（下地 → 仕上げ → 設備）が崩れる。行の並びは数量リストの順を
そのまま保つ。

## 見本データ

`examples/` は**生成物**。家具は実在する 3D カタログから引き、仕上げ材・建具・電気は
手で書いた架空の行が残っている。**単価はすべて架空**（カタログに価格は無い）。

```bash
uv run python tools/make_examples.py \
    --manifest ../TemplateMaker/catalog/abo.tier-b.json
uv run python tools/make_examples.py --check    # 生成せず、一致するかだけ見る
```

手で書いた家具を並べると、**寸法も品目の幅も作り手の想像の範囲に収まる**。実在する
カタログから引くと、寸法のばらつきも品目の偏りも実物のものになり、表示幅や科目の
分かれ方が本当に耐えるか分かる。

道具が読むのは**マニフェスト 1 枚だけ**で、`tm-manifest-1` の形をしていれば出どころは
問わない（道具のコードに出どころの名前は出てこない。ライセンスも帰属表記もマニフェスト
から読んで写す）。3D の実体も商品画像も読まない —— 見積書は文字しか出さないので、
読んでも置き場所が無い。

**乱数を使わない。** 同じマニフェストと同じ引数なら出力は 1 バイトも変わらない。
`--seed` という引数を作らないことで、それを形にしてある。

置き方の 4 区分（床置き・敷物・壁付け・天井）が**科目・職種・歩掛りのすべてを決める**。
同じカタログの 1 体が、置き方が違うだけで別の科目に行く。

| 置き方 | 科目 / 中科目 | 職種 |
|---|---|---|
| 床置き | 家具工事 / 置き家具 | 家具工 |
| 敷物（ラグ） | 家具工事 / 敷物 | — |
| 壁付け | **内装工事** / 壁付け（下地共） | 大工 |
| 天井（照明） | **電気設備工事** / 照明器具 | 電工 |

壁付けを内装工事に置くのは下地（間柱・合板）が要るため。下地は内装の仕事で、家具の
据付ではない。**手間の性質が違うものを同じ中科目に入れると、後から歩掛りを直すときに
巻き添えが出る。**

## 階層と税区分

建築工事内訳書の標準書式に合わせて **科目 → 中科目 → 細目**の 3 段で積む。

```
内装工事                        科目
  壁・天井仕上                  中科目
    量産クロス  48.6 ㎡          細目（＝明細の 1 行）
```

2 段で足りるように見えても、**後から段を増やすと既存の単価表を全部棚卸しし直す**
ことになる。段は先に用意しておくほうが安い。

税区分は品目ごとに持ち、**区分ごとの小計まで出す。消費税額は出さない**（直接工事費
までが担当）。それでも区分を運ぶのは、課税・非課税・立替金が混ざった明細を**後から
行に遡って分けることができない**ため。

総計は「合計」としか名乗らない。諸費用の科目を単価表に置けるので、**何が入っている
かは表を組んだ人しか知らない**。「直接工事費」と書くと嘘になりうる。

## 単価の付かない行

**落とさずに残す。** 黙って落とすと合計だけが静かに小さくなり、見積りが足りない
ことに気づけない。金額を持たない行として最後まで運び、人の目に触れさせる。

```
単価が付かなかった行が 1 件ある。合計はその分だけ足りない。
  TILE-9999  4.5  浴室タイル。単価表にまだ無い
```

単価の**出どころが書かれていない行**も同じように数えて出す。後から金額の根拠を
たどれないため。

自動で回すなら `--strict` で失敗にできる。

```bash
uv run estimate run q.json --strict       # 単価の付かない行があれば exit 1
uv run estimate check q.json              # 突き合わせだけ。金額を出さない
```

単価表の不備は**全部ためてから**投げる。1 つ直すたびに次の 1 つが出るのでは、表を
直す側が何度も往復することになる。

```
prices.csv:2: code が空
prices.csv:3: B の unit が空。数量の意味が決まらない
prices.csv:4: C の職種 左官 が労務単価表に無い
```

## 書き出し

```bash
uv run estimate run q.json --format json -o out/estimate.json
uv run estimate run q.json --format csv  -o out/estimate.csv
```

| | |
|---|---|
| `text` | 端末の表。既定 |
| `json` | 機械向け。**金額は整数、数量と人工は文字列** |
| `csv` | 表計算向け。**明細と段だけ。小計は入れない** |
| `html` | **客先に出せる見積書。** ブラウザで開いて印刷、または PDF として保存 |

JSON で数量を文字列にするのは、受け手が float で読んで末尾を濁らせないため。円は
整数なので数のまま出す。

CSV に小計を混ぜないのは、取り込んだ先で合計を取り直したときに二重に数えるため。
**段の金額は小計ではなく新しく足す額**なので入れ、節目（純工事費・工事原価）と累計は
入れない。この線を守ると `SUM(amount)` が税込合計にちょうど一致する。

端末の表は**全角を 2 幅で数える**（`unicodedata.east_asian_width`）。品目名が日本語
なので、文字数で揃えると列が必ずずれる。

### 見積書（`html`）

```bash
uv run estimate run q.json --markup markup.csv --format html -o 見積書.html
```

端末の表・JSON・CSV は作業用で、**客先に出せる形はこれだけ**。A4 縦・実寸で、
ブラウザの印刷から PDF として保存できる。

**PDF は自前で書かない。** 日本語を PDF に埋めるには CID フォントのサブセット埋め込みが
要り、「外部依存なし」という方針と正面衝突する。ブラウザに任せればフォントも正しく出る
（[MiniCAD][mc] の `print.ts` と同じ判断）。

**出せない状態なら紙にそう書く。** 発行者が未記入、単価の付かない行がある、認定欄が
空いている——どれも注意書きとして紙に出る。**黙って出さないのが一番困る。**

## テスト

```bash
uv run pytest tests -q     # 219 件
```

計算の規約（ロスの掛かり方・丸め・人工・段の積み方）は、**数字を直したら落ちる**
ように書いてある。見積りの金額は後から検算されるので、規約が黙って変わるのが一番困る。

**そのための固定の表をテストの中に持っている。** 規約の検算を `examples/` に乗せると、
見本を作り直すたびに巻き添えで落ち、「規約が変わった」のか「見本が変わった」のかが
分からなくなる。見本を見るテストは**金額を固定せず、整合性だけ**を見る
（合計が行の和に一致する、税区分の小計の和が合計に一致する、など）。
